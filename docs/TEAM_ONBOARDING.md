# Подключение участников команды

## 1. Статус приглашений

Руководитель сообщил, что приглашения коллегам в GitHub отправлены. Факт принятия приглашений пока не подтверждён.

Не считать участника подключённым до проверки:
- GitHub invite принят;
- участник видит приватный репозиторий;
- участник может открыть Issues;
- согласована роль и зона ответственности.

## 2. Данные, необходимые для назначения

Для каждого участника зафиксировать:
- GitHub login;
- подтверждение доступа;
- основная зона ответственности;
- резервная зона;
- удобный канал оперативной связи;
- часовой пояс и доступность во время 48-часового спринта.

Не публиковать личные контакты в открытом репозитории.

## 3. Роли по умолчанию

- Дмитрий — Project Lead / System Integrator.
- Участник A — Backend / ML Integration / RAG.
- Участник B — Frontend / QA.

Это распределение ролей, не назначение конкретных людей. Персональные назначения выполняются после подтверждения логинов и согласия участников.

## 4. Обязательное ознакомление

Каждый участник должен прочитать:
1. README.md;
2. PROJECT_CHARTER.md;
3. ARCHITECTURE.md;
4. BACKLOG.md;
5. TEAM_RULES.md;
6. TEST_PLAN.md;
7. MISSING_INPUTS.md;
8. TASK_SPECIFICATIONS.md — свою зону ответственности.

## 5. Подтверждение готовности участника

Участник отвечает в командном канале:
- доступ к репозиторию подтверждён;
- документы прочитаны;
- зона ответственности принята;
- доступ к среде разработки проверен;
- известные ограничения сообщены;
- временная доступность на спринт подтверждена.

## 6. Правило единого Codex

Команда использует один общий Codex и один репозиторий. Поэтому:
- не запускать независимые конкурирующие изменения через Codex;
- не выдавать Codex две задачи, меняющие одни файлы;
- все изменения передавать через одну очередь;
- каждый участник отвечает за подготовку требований, проверку результата и тесты в своей зоне;
- руководитель управляет очередью и интеграцией.

## 7. Минимальный формат передачи работы

Передача должна содержать: Issue ID, цель, входные данные, ожидаемый результат, критерии приёмки, тесты, изменённые файлы и блокировки.
