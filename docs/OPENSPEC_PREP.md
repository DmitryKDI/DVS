## Разрешено сейчас (до старта)

- Проверить целевую ОС и среду участников, версии и наличие Codex, Node/пакетного менеджера или поддерживаемого альтернативного способа установки; **не предполагать**, что Node/Docker уже установлены.
- При необходимости установить универсальную OpenSpec CLI **вне репозитория DVS** и проверить её версию, не изменяя файлов конкурсного проекта. Пример из официальной документации (только при совместимой среде): `npm install -g @fission-ai/openspec@latest`; фактический результат и версию записать в PREP-008.
- Создавать только текстовые планы и схемы. Пока **не запускать** `openspec init` внутри DVS; не добавлять `openspec/`, `.agents/`, сгенерированные навыки Codex, `AGENTS.md` с рабочими промптами, реализационные конфигурации и проектные OpenSpec changes.
- Учитывать, что репозиторий на 23.11.2026 **public** по GitHub API. Перед коммитом проверять секреты, права на документацию, синтетические данные и лицензии.

## Только после разрешённого старта

1. Получить и проверить фактические OpenAPI, данные, справочник F01–F14 и шесть PDF заказчика; зафиксировать версии/ограничения и blocked.
2. Проверить `openspec --version`, `openspec init --help` и совместимость с Codex. При подтверждённом синтаксисе использовать `openspec init --tools codex` **в отдельной ветке**; иначе следовать реальной инструкции CLI.
3. Сделать diff и аудит созданных файлов; оставить только нужную интеграцию, не включать секреты, незапрошенные сервисы и чужие PDF.
4. Сопоставить GitHub Issue ↔ OpenSpec change ↔ PR; в спецификации отделять требование заказчика, доказательство (OpenAPI/файл/PDF-страница), инженерное решение и неизвестное. Не придумывать API-поля и нормы.
5. Запустить доступные проверки CLI, проверить одну пробную интеграцию с Codex, ревью diff и ИБ; зафиксировать команды, версии, результаты. Только после ревью разрешать merge.
