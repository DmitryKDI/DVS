# Tasks

## 1. P0. Первый локальный сквозной прогон

- [x] 1.1 Подключить карточку одного синтетического автомобиля к существующей заглушке ML. Тестами подтвердить привязку к машине, маркировку синтетики и отсутствие диагноза или заявки при плохой записи, неизвестном статусе и недоступности.
- [x] 1.2 Подключить синтетический документ к проверке применимости. Тестами проверить правильный документ и страницу, отказ для чужого двигателя и состояние без доказательства.
- [x] 1.3 Собрать черновик, подтверждение версии и тестовый приёмник заявок. Тестами подтвердить блокировку отправки до подтверждения и после редактирования, а также отсутствие внешних вызовов в локальном режиме.

- [x] 1.4 Сверить локальный каркас с REQ-007–010 и T-009–013. Проверить фрагмент по странице синтетического руководства и точной модификации двигателя. Раздельно показать результат ML, гипотезу и сведения из источника. Тестами отклонить чужую модификацию, неверную страницу и неподтверждённую цитату.

## 2. P0. Подключение материалов организатора

- [ ] 2.1 Сверить данные автопарка и диагностики, справочник F01–F14, OpenAPI ML и ответы стенда (#11–#13). Прогнать корректный запрос для одного автомобиля и проверить обработку фактических статусов. При отсутствии входных данных записать точный блокер.
- [ ] 2.2 Проверить применимость полученных PDF и подключить извлечение и поиск (#14–#17). Сверить возвращённую страницу и процедуру с оригиналом, проверить документ другого двигателя.
- [ ] 2.3 Сверить OpenAPI ТОиР и подключить отправку подтверждённой версии (#18–#19). Проверить ответ стенда и безопасное поведение при ошибке и неопределённом исходе.
- [ ] 2.4 Собрать экраны и провести сквозную приёмку (#20–#26). Проверить чистый запуск, успешный сценарий одного автомобиля, отказ при плохой записи и блокировку неподтверждённой заявки. Записать результаты отдельных локальных и стендовых прогонов.

## Workflow follow-up
