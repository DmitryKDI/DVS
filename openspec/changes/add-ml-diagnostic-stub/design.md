# Design

## Context

В DVS описана граница между адаптером ML и нормализацией. Внешние поля, статусы и пороги ещё предстоит подтвердить по OpenAPI и стенду.

## Goals / Non-Goals

**Goals:** Проверить выбор источника и обработку диагностических исходов на воспроизводимых данных.

**Non-Goals:** Сетевой имитатор внешнего ML API, реальные диагностические данные и интеграция с ТОиР.

## Decisions

1. Заглушка работает в процессе на внутренней границе диагностики. Это позволяет проверить поведение DVS без HTTP-сервера и без предположений о внешних схемах.
2. Тест явно выбирает сценарий. Результат маркируется как синтетический. Отказ реального источника в обычном режиме остаётся видимым.
3. Норма и отклонение проверяют обработку успешного результата. Плохая запись, неизвестный статус и недоступность проверяют отдельные пути отказа. Имена внутренних состояний не задают внешний контракт.

## Risks / Trade-offs

- Синтетический сценарий может создать ложное ощущение готовности интеграции. Проверка реального ML требует отдельного прогона по OpenAPI и стенду.
- Случайное включение заглушки могло бы подменить реальную диагностику. Тестовый режим выключен по умолчанию, отсутствие автоматической подмены покрывается тестом.
